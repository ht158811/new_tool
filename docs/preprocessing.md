# 数据预处理模块

数据预处理页只处理项目首页当前选中的数据集。开始按钮需要同时满足：数据集已完成完整扫描、已选择输出目录、已人工选择一个处理功能。裁剪、增强和转换互斥执行，不会自动串联。

## 安全边界

- 源图片和 LabelMe JSON 只读；输出目录不能等于源目录或位于源目录内部。
- 每次任务默认创建 `Crop_日期_序号`、`Augmentation_日期_序号` 或 `Conversion_日期_序号` 独立目录；用户也可填写合法的自定义目录名。已有目录一律不覆盖。
- 执行期间先写任务专属临时目录；取消或失败只清理该临时目录。
- 完成后写入 `result_manifest.json`，记录输入数据集标识、范围、参数、数量、警告和时间，但不写入源数据绝对路径。
- 损坏 JSON 在“全部图片”范围中仅处理图片并明确记录警告，不会被当成“无 JSON”。
- 裁剪和增强结果保持原图片扩展名与 LabelMe JSON 格式。图片和同名 JSON 全部平铺到结果目录的 `data` 文件夹，不保留源文件夹层级；文件名附加稳定短标识，避免不同源目录中的同名文件互相覆盖。manifest 位于结果根目录，不会被误识别为 LabelMe 标注。
- 只有格式转换会按照 YOLO、COCO 或 VOC 的目标规范创建 `images`、`labels` 等结构。

## 已实现算法

- 裁剪：按用户设置的行数×列数均匀分块。使用整数边界 `index * size // count` 分配不能整除的余数，保证覆盖整张图片且无遗漏、无重叠；rectangle、polygon、point、line 和 linestrip 会按每个分块的真实边界裁切并转换为分块局部坐标。旧 JSON 缺少 `shape_type` 时，两个点按 rectangle、其他点按 polygon 兼容处理。
- 增强：水平/垂直翻转、90/180/270 度旋转、亮度、对比度、饱和度、高斯模糊和高斯噪声；支持固定随机种子和多操作组合。
- 标签分割：按用户输入的分隔符首次出现位置拆分 `shape.label`。`before` 和 `after` 两套输出独立设置是否生成、标签保留方式和目录分组；标签保留方式均提供“前标签保留”“后标签保留”“前后标签同时保留”。启用分组后直接以该输出实际保留的标签对象作为目录名，不追加哈希；Windows 禁止字符使用下划线替换，例如 `banmian:bansun` 生成目录 `banmian_bansun`。分组 JSON 只保留当前目录标签的 shapes。没有分隔符时保留原标签，不再提供标签置空或跳过 shape。
- 批量标签重命名：输入原标签名和目标标签名，精确替换有效 LabelMe JSON 的 `shapes[].label`，不执行包含匹配或模糊匹配。输出保持 LabelMe 图片与同名 JSON 格式，保留坐标、其他 shapes 和未知字段，源数据只读。
- 图片质量：标签分割和格式转换等复制场景直接复制源文件并进行 SHA-256 字节一致性校验；裁剪、增强等必须重编码的图片使用对应格式的最高质量或无损参数。
- 文件命名：保留原文件名主体，只追加最短操作标识；仅在原文件名冲突时追加最短数字编号，禁止使用无必要的长哈希重命名。
- 转换：目标检测 YOLO TXT、COCO JSON、Pascal VOC XML。rectangle 可无损转换；其他 shape 会阻止转换并报告原因。

## 暂不猜测的业务规则

- 图像分类需要明确的图像级类别来源，不能直接把 `shape.label` 当作整图类别。
- 语义分割的目标格式尚未指定。
- polygon 转检测框会损失信息，因此当前不自动转换为外接矩形。
